## Elicitation usages

Permalink base: `https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/`

All forms are **action-only**: `requestedSchema` is `{type: "object", properties: {}}`, so consent is the `accept` / `decline` / `cancel` action itself ([tools/confirmation.ts#L501](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/tools/confirmation.ts#L501)). Each prompt mints an HMAC-signed `requestState`, bound to `<method>:<principal>`, that carries the tool, its arguments (or a hash of the SQL / notebook cells) and `issued_at`. The default TTL is 600 s. On retry the server checks the state belongs to this tool and the arguments still match, and reprompts if the quoted cost has changed.

## Fallback without client elicitation support

The server reads capability **per request** from the 2026-07-28 envelope (`_meta` protocol version + client capabilities). `elicitation: {}` or a `form` key counts as form-capable, and a `url` key as URL-capable ([tools/confirmation.ts#L511](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/tools/confirmation.ts#L511), [#L534](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/tools/confirmation.ts#L534)). A pre-2026 client is never form-capable, even if it declared elicitation at `initialize`. The fallback differs per feature:

| Feature | Without the capability |
|---|---|
| Cost (`create_project`, `create_branch`) | Legacy two-tool flow: `get_cost` -> the model tells the user -> `confirm_cost` returns a hash -> pass it as `confirm_cost_id`. A missing or mismatched ID is a `ToolCallerError` with instructions ([tools/account-tools.ts#L421](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/tools/account-tools.ts#L421)). For form-capable clients the server drops `confirm_cost_id` from the schema and hides `get_cost` / `confirm_cost` ([server.ts#L475-L493](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/server.ts#L475-L493)). |
| Destructive SQL (`execute_sql`, `apply_migration`) | **Fail-open**: runs with no prompt, recorded as `route: bypass, reason: capability_missing` ([tools/database-operation-tools.ts#L580](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/tools/database-operation-tools.ts#L580)). The option's doc says so: "Clients without form capability run raw SQL without a prompt" ([server.ts#L119](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/server.ts#L119)). |
| Notebooks (`run_notebook` with mutating cells, `delete_notebook`) | **Fail-closed**: `ToolCallerError` "...this client does not support form elicitation. No cells were run. Use a client with form elicitation support or run in read-only mode." / "...delete it from the Supabase dashboard." ([tools/notebook-tools.ts#L570](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/tools/notebook-tools.ts#L570), [#L748](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/tools/notebook-tools.ts#L748)) |
| Secret collection | **Tool hidden** from `tools/list` for clients that are not URL-capable ([server.ts#L438](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/server.ts#L438)). A direct call returns `isError` `{status:"unsupported_client"}` "This client cannot open a browser page. Add the secret in the dashboard under Edge Functions > Secrets." ([tools/secret-tools.ts#L150](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/tools/secret-tools.ts#L150)) |

Elicitation is opt-in for whoever embeds the server: no `elicitation` option, no prompts. The stdio CLI (`npx @supabase/mcp-server-supabase`) passes none, so local stdio users always get the legacy cost flow and unprompted SQL ([cli.ts#L119](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/cli.ts#L119)). The local HTTP entry enables all six confirmations and lets the user opt out per tool with `?skip_elicitations=execute_sql,...` ([transports/local-http-entry.ts#L42](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/transports/local-http-entry.ts#L42)).

## Other human-in-the-loop mechanisms

- `get_cost` / `confirm_cost` / `confirm_cost_id`: the pre-elicitation, model-mediated cost confirmation, kept as the fallback (described above).
- `read_only=true` (URL query or `--read-only`): write tools are hidden, `execute_sql` runs as a read-only Postgres role, and its `readOnlyHint` flips to true ([tools/database-operation-tools.ts#L561](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/tools/database-operation-tools.ts#L561)).
- `project_ref` scoping and `features=` feature-group allowlist.
- `readOnlyHint` / `destructiveHint` annotations on every tool.
- SQL results wrapped in an "untrusted data" boundary against prompt injection.

## Notes

- This is the most complete SEP-2322 adopter in the batch. It uses only the stateless `InputRequiredResult` path (no server-to-client requests), with signed, principal-bound, TTL'd `requestState`, argument binding, quote-change reprompts and an expiry wrapper (`stopExpiredState`).
- Telemetry flags "instant" cancels: under 1 s from issue to cancel ([tools/confirmation.ts#L247](https://github.com/supabase-community/supabase-mcp/blob/9092ab9055509fcdfbedcb75edf02d9412feed37/packages/mcp-server-supabase/src/tools/confirmation.ts#L247)). A code comment cites logs showing about 0.55 s client auto-cancels, so some clients cancel elicitations without showing them. The cancel message tells the model as much.
- The policy is deliberately asymmetric: SQL fails open, so as not to break existing agents, while notebook mutations and deletes fail closed and secrets are hidden. Decline and cancel are normal results, not `isError`. Expired or tampered state is `isError`.
- Cost elicitation is skipped when the next project would cost $0, so no prompt appears for free-tier projects.
