# mcp-architecture

The architecture every Python MCP generated by `packages/mcp-scaffold` keeps, as a pytest plugin.
A rule lives here once, so fixing or tightening it reaches every MCP with `uv sync`, and no MCP
carries a copy it could loosen. [`ARCHITECTURE.md`](ARCHITECTURE.md) explains the architecture and
each rule, and the `AGENTS.md` of every scaffolded MCP points to it.

## Install

A dev dependency only; the image never installs it:

```toml
[dependency-groups]
dev = ["mcp-architecture==0.1.0"]

[tool.uv.sources]
mcp-architecture = { path = "../../packages/mcp-architecture" }
```

```toml
[tool.ruff]
extend = "../../packages/mcp-architecture/src/mcp_architecture/code_style.toml"

[tool.basedpyright]
extends = "../../packages/mcp-architecture/src/mcp_architecture/type_check.json"
```

The scaffold writes this and the `[tool.importlinter]` table, from `render_importlinter`.

## The plugin

In a project whose `pyproject.toml` declares `[tool.importlinter]`, the plugin adds
`service_tests` to its `tests/` package, listed as `tests/mcp_architecture.py`, a module that is
not on disk. Its tests see the project's `tests/conftest.py`, and need a `server` fixture there
that returns the FastMCP server:

- `test_the_service_keeps_the_architecture`, once per rule in `RULES`.
- `test_every_tool_and_parameter_is_described`.
- `test_the_tools_served_match_their_snapshot`, against `tests/tool_surface.generated.json`.
  `uv run pytest --regen-all` writes it.

`uv run pytest -k mcp_architecture` runs them alone.

## What it gives

- `RULES`: each `Rule` has a `name`, a `summary` of what it checks and `check(Service) ->
  list[str]`, the problems it found. `Service(root)` reads the package from
  `[tool.importlinter] root_package`. `ARCHITECTURE.md` says why each rule exists, and a test
  fails when a rule is missing from it.
- `render_importlinter(package)`: `[tool.importlinter]` with the required contracts, as TOML.
- `code_style.toml`: the code style every MCP keeps, the Google Python Style Guide as far as ruff
  checks it, with lines to 100 characters and docstrings only where the code cannot say it. An
  MCP's `[tool.ruff]` sets `extend` to it, so `ruff check --fix` fixes what it can, and the
  `code-style` rule runs it whatever that table says.
- `type_check.json`: basedpyright's `all` mode, with the reports every MCP turns off. An MCP's
  `[tool.basedpyright]` extends it, and the `type-check` rule fails on a `typeCheckingMode`, an
  `ignore` or a report turned down there, since basedpyright lets each override it.
- `FeaturePrivacyContract` and `CommandQuerySeparationContract`, the import-linter contract
  types `CONTRACT_TYPES` registers.
- `undescribed_tools(server)`: each tool without a description and each parameter without one,
  skipping a tool tagged `passthrough` (served straight from an OpenAPI spec).
- `tool_surface(server)`: the tools the server lists (name, title, description, input and output
  schema, annotations and tags) as JSON, for pytest-regressions' `file_regression`.

## Working on the package from a service

A service installs the package as a copy, so an edit here is not seen until
`uv sync --reinstall-package mcp-architecture` in the service.

## Checks

```sh
uv sync
uv run pytest
uv run ruff check . && uv run ruff format --check .
uv run basedpyright
```

CI runs the same sequence here, and every service that depends on the package.
