# mcp-architecture

The architecture every Python MCP generated by `packages/mcp-scaffold` keeps, as configuration
for the tools that check it: ruff, basedpyright and import-linter. A rule lives here once, so
tightening it reaches every MCP with `uv sync`.
[`ARCHITECTURE.md`](ARCHITECTURE.md) explains the architecture and names the tool behind each
rule, and the `AGENTS.md` of every scaffolded MCP points to it.

## The rules

| Rule | Checked by |
|---|---|
| Layers only import downwards: `main → mcp → contexts → upstream / persistence → telemetry` | import-linter |
| A layer is imported through its top level, and `contexts` through `<package>.contexts` | import-linter |
| A feature imports another only through that feature's top level | `FeaturePrivacyContract` |
| No package imports its siblings in a cycle, at any depth | import-linter |
| `contexts` and `persistence` import nothing from `fastmcp`, `mcp` or `mcp_types` | import-linter |
| Every Python folder has an `__init__.py`, and imports are absolute | ruff |
| A context function takes keyword arguments only | ruff |
| APIs a past fix replaced stay banned | ruff |
| The Google Python Style Guide, as far as ruff checks it | ruff |
| Every type is known | basedpyright |
| No file changes its own type check | `files_changing_their_type_check` |
| Every tool and parameter has a description | `undescribed_tools` |
| No tool schema combines schemas at its root | `tools_with_a_root_combinator` |
| An unexpected error reaches the client without its message | `masks_error_details` |
| A settings error does not print its input | `settings_showing_input_in_errors` |
| What a client sees matches a snapshot | `tool_surface` |
| The MCP's tool tables keep every shared rule and contract | `loosened_configuration` |
| `contexts` is flat, one folder per feature | review |

A rule checked by a name in code, not a tool, is code of our own.
[`CUSTOM_CHECKS.md`](CUSTOM_CHECKS.md) says why, and which tools we looked at instead.

## Install

A dev dependency only; the image never installs it:

```toml
[dependency-groups]
dev = ["mcp-architecture==0.1.0"]

[tool.uv.sources]
mcp-architecture = { path = "../../packages/mcp-architecture" }

[tool.ruff]
extend = "../../packages/mcp-architecture/src/mcp_architecture/code_style.toml"

[tool.basedpyright]
extends = "../../packages/mcp-architecture/src/mcp_architecture/type_check.json"
```

The scaffold writes this, the `[tool.importlinter]` table from `render_importlinter`, and
`tests/offline_server.py`, whose `offline_server()` builds the server with fakes in place of the
upstream and the stores.

## What it gives

- `code_style.toml`: the code style every MCP keeps, the Google Python Style Guide as far as ruff
  checks it, plus the APIs a past fix replaced. An MCP's `[tool.ruff]` extends it.
- `type_check.json`: basedpyright's `all` mode, with the reports every MCP turns off. An MCP's
  `[tool.basedpyright]` extends it.
- `render_importlinter(package)`: `[tool.importlinter]` with the contracts every MCP keeps, as
  TOML. import-linter cannot extend a shared file, so the scaffold writes it into each MCP.
- `FeaturePrivacyContract`: the one contract type of our own, which the rendered table
  registers. import-linter's `protected` contract lets an allowed importer's descendants in too,
  so it cannot say that one feature only reaches another through its top level.
- `mcp-architecture-check`: runs, in the MCP's folder, the checks of what a client sees against
  the server `offline_server()` builds, and checks the MCP's tool tables in `pyproject.toml`. CI
  runs it as a step of its own, outside pytest, so a `conftest.py` cannot skip, xfail or deselect
  a check. `--update` writes
  `tests/tool_surface.generated.json` instead of comparing with it. The checks it runs:
  - `undescribed_tools(server)`: each tool without a description and each parameter without one,
    skipping a tool served straight from an OpenAPI spec, which says what the spec says.
  - `tool_surface(server)`: the tools the server lists (name, title, description, input and
    output schema, annotations and tags) as JSON, compared with the snapshot.
  - `tools_with_a_root_combinator(server)`: each tool whose input schema has `anyOf`, `oneOf`,
    `allOf` or `not` at its root.
  - `masks_error_details(factory)`: whether an unexpected error reaches the client without its
    message. It adds a tool that raises to a server of its own from `offline_server`, and calls
    it.
  - `settings_showing_input_in_errors(package)`: each settings class whose validation error
    would print the value it was given.
  - `files_changing_their_type_check(root)`: each `# pyright:` comment in `src` and `tests` that
    sets a file's mode or a report, which basedpyright honours whatever the shared config says.
    Only an ignore that names its rule is left.
  - `loosened_configuration(root, pyproject, package)`: each contract or import-linter option
    that differs from what `render_importlinter` writes, a missing `extend` of `code_style.toml`
    or `type_check.json`, a ruff `select`, `ignore` or `extend-ignore`, and a basedpyright mode,
    ignored path or report turned down. A contract of the MCP's own after the shared ones, a
    stricter report and a ruff `per-file-ignores` entry pass.

## Working on the package from a service

ruff and basedpyright read `code_style.toml` and `type_check.json` from this folder, so an edit
there reaches a service at once. A service installs the Python code as a copy, so an edit to it
is not seen until `uv sync --reinstall-package mcp-architecture` in the service.

## Checks

`scripts/check-python-service.sh` runs the tools on an MCP in the order CI does. `DEVELOP.md`
lists the steps. Here:

```sh
uv sync
uv run pytest
uv run ruff check . && uv run ruff format --check .
uv run basedpyright
```

CI runs the same sequence here, and every service that depends on the package.
