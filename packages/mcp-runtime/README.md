# mcp-runtime

What every Python MCP server shares at run time, so a service imports it instead of keeping a
copy: the settings with the defaults we always use, the HTTP server with its host and origin
guard, the telemetry setup and the retrying transport of a plain HTTP upstream. A fix here
reaches every MCP with a version bump.

Its siblings split the rest: `mcp-architecture` checks the structure an MCP keeps, and
`mcp-scaffold` generates a new MCP once.

## Server

```python
from mcp_runtime import ServerSettings, http_app, run_server

run_server(mcp, ServerSettings(), [instrument(mcp)])
```

`run_server` serves the FastMCP app over streamable HTTP at `/mcp`, stateless, without uvicorn's
access log. It refuses to start when the server has no auth provider (`FastMCP(auth=...)`) and
`HOST` is not loopback, so an MCP without auth runs locally but never in a pod. `http_app` builds
the same app for tests. Both put the same middleware first:

1. A host and origin guard: a request must name a host of `MCP_BASE_URL` (or `localhost`) and,
   from a browser, an allowed origin. `/probe`, `/health` and `/metrics` skip it, since
   Kubernetes and Prometheus reach the pod by IP.
2. CORS for `MCP_ALLOWED_ORIGINS`.
3. The MCP's own middleware, in the order it passes them.

MCP-level middleware, which sees tool calls rather than HTTP requests, goes on the server
itself: `mcp.add_middleware(...)`.

## Telemetry

```python
from mcp_runtime import LoggingSettings, init_telemetry, instrument

init_telemetry("weather-mcp", LoggingSettings())
middleware = instrument(mcp)
```

`init_telemetry` runs before anything logs. It configures JSON logs in the format Loki expects,
with trace ids, and OpenTelemetry tracing under the service's name and installed version, off
unless `OTEL_TRACES_EXPORTER` is set. `instrument` mounts `/probe`, `/health` and `/metrics`,
counts, times and logs every tool, resource and prompt call, and returns the HTTP metrics
middleware to pass to `run_server`. A scaffolded MCP calls both from its own
`telemetry/setup.py`.

## Upstream retries

```python
http = httpx2.AsyncClient(
    transport=RetryingTransport(httpx2.AsyncHTTPTransport(), RetrySettings()), ...
)
```

`RetryingTransport` sends a request again on a status in `RetrySettings.statuses`, after its
`Retry-After` in seconds, or an exponential backoff without one, as long as the wait stays
within `max_wait_seconds`. It resends any request on a 429, but a POST or PATCH on no other
status, since a gateway's 503 may come after the upstream applied it. It returns the last response, so the client's own hook decides what an
error status raises.

## Settings

Each class reads the environment and a `.env` file the same way (`shared_config`).

| Class | Env | Defaults |
|---|---|---|
| `ServerSettings` | `HOST`, `PORT`, `MCP_BASE_URL`, `MCP_ALLOWED_ORIGINS` | `127.0.0.1:8000`; the base URL from them; the MCP Inspector's origin on localhost. A remote base URL needs https and no path. |
| `RedisSettings` | `REDIS_URL` | required |
| `PostgresSettings` | `DATABASE_URL` or `DB_URL`, or `DB_HOST`/`DB_PORT`/`DB_NAME`/`DB_USER`/`DB_PASSWORD`; `PG_DATABASE_SSL_MODE`, `DB_SSL_ROOT_CERT`, `DB_POOL_SIZE`, `DB_MAX_OVERFLOW` | pool 5 + 10 overflow. `connection_url` and `connect_args` are ready for `create_async_engine` with asyncpg. |
| `ZitadelSettings` | `ZITADEL_BASE_URL`, `ZITADEL_CLIENT_ID`, `ZITADEL_CLIENT_SECRET`, `ZITADEL_JWT_SIGNING_KEY`, `ZITADEL_ORG_ID` | https outside localhost; a public PKCE client without a secret; `openid profile urn:zitadel:iam:user:resourceowner`, plus the organisation scope when set |
| `RetrySettings` | `UPSTREAM_RETRY_MAX_ATTEMPTS`, `UPSTREAM_RETRY_MAX_WAIT_SECONDS`, `UPSTREAM_RETRY_STATUSES` | 5 attempts, at most 30 s apart, on 429 and 503 |
| `LoggingSettings` | `LOG_LEVEL`, `LOGS_DIAGNOSTICS_DATA_POLICY` | `INFO`; identifying values concealed as `sha256:<hex>` |
| `ElicitationSettings` | `ELICITATION_FOR_DISAMBIGUATION`, `ELICITATION_FOR_DATA_MODIFICATION`, `ELICITATION_FOR_DATA_REMOVAL` (`enabled` or `disabled`), `ELICITATION_TIMEOUT_BEFORE_CANCEL_SECONDS` | all enabled; 120 s |

The Postgres names are the ones the base Helm chart injects, and the Zitadel names match
`unique_mcp.auth.zitadel.ZitadelOIDCProxySettings`. A service with a second upstream reads its
retries under another prefix: `RetrySettings(_env_prefix="BILLING_RETRY_")`.

## Install

```toml
dependencies = ["mcp-runtime==0.1.0"]

[tool.uv.sources]
mcp-runtime = { path = "../../packages/mcp-runtime" }
```

A service Dockerfile has to `COPY packages/mcp-runtime` before `uv sync`. An MCP generated by
`packages/mcp-scaffold` has all of this already.
