# A2A compatibility profile

## Pinned profile

| Item | Decision |
| --- | --- |
| Protocol version | **A2A 1.0** only. `A2A-Version` header validated; other versions → `-32009 VersionNotSupported`. No 0.3 methods, no 0.3 wire shapes. |
| Binding (server) | JSON-RPC 2.0 over HTTPS, `Content-Type: application/json`. SSE for `SendStreamingMessage` / `SubscribeToTask`. |
| Binding (client) | JSON-RPC only. Remote cards offering only REST/gRPC are rejected at connection test. |
| SDK | `@a2a-js/sdk` **1.2.x** (server: `DefaultRequestHandler`, `jsonRpcHandler` on Express; client: `ClientFactory` + `JsonRpcTransportFactory`). Peer deps: `express` (already used via NestJS platform-express). gRPC peers not installed. The SDK's `compat/v0_3` subpaths are **not** imported. |
| Agent Card | Per publication, `supportedInterfaces: [{ url, protocolBinding: "JSONRPC", protocolVersion: "1.0" }]`, `securitySchemes: { zitadel: openIdConnect(openIdConnectUrl) }`, `security: [{ zitadel: ["openid","profile"] }]`. `capabilities: { streaming: true, pushNotifications: true, extendedAgentCard: true }`. No card signatures in this delivery. |
| Extensions | none declared, none honoured. |
| Task ids / context ids | UUID v4 generated by the gateway; client-provided `taskId` only accepted for follow-ups on existing tasks. |

## Content and interaction matrix

| Capability | Inbound (server) | Outbound (client) |
| --- | --- | --- |
| `text` parts | ✅ | ✅ |
| `data` parts (JSON) | ✅ as input (forwarded as fenced JSON in the message text; schema answers for elicitation) · ✅ as output (references, structured elicitation schema) | ✅ input → JSON text; ✅ output → rendered as fenced JSON in the assistant message |
| `file` parts, inline bytes | ✅ up to `MAX_INLINE_FILE_BYTES` (default 10 MB) → uploaded to the chat | ✅ same limit, remote file uploaded to the chat |
| `file` parts, URI | ✅ outbound artifacts via gateway download URL (Bearer) · ❌ inbound URI fetch (client must send bytes) | ✅ download through egress guard, `MAX_REMOTE_FILE_BYTES` |
| Streaming (SSE) | ✅ | ✅ when card declares `streaming`, else poll |
| `SubscribeToTask` | ✅ (poll-backed, see D-07) | ✅ if peer supports, else poll |
| Cancellation | ✅ | ✅ if peer supports (`CancelTask`), else best effort: stop writing, mark stopped |
| `INPUT_REQUIRED` | ✅ ⇄ Unique FORM elicitation | ✅ ⇄ Unique FORM elicitation (schema from `data` part) or free-text follow-up |
| `AUTH_REQUIRED` | ✅ ⇄ Unique URL elicitation | ✅ ⇄ Unique URL elicitation (url from status message) |
| Push notifications | ✅ | ❌ not used as client (we stream/poll) |
| Extended agent card | ✅ (adds skills hidden from public card) | ✅ read if advertised |
| `ListTasks` | ✅ scoped to caller | n/a |
| Multi-turn (`contextId`) | ✅ 1 context = 1 chat | ✅ 1 chat = 1 remote context |
| Unsupported modes | reject with `-32005 ContentTypeNotSupported`; never flatten silently | reject at send when part kind not in peer `defaultInputModes`; never silently drop |

Negotiation: connection test stores the remote card's `capabilities`, `defaultInputModes`, `defaultOutputModes`, `supportedInterfaces`. The space settings UI shows the resulting matrix; runtime enforces it.

## Peer limitations recorded (client's LangSmith Agent Server)

Source: [docs.langchain.com/langsmith/server-a2a](https://docs.langchain.com/langsmith/server-a2a), to be **re-verified against the client's deployed `langgraph-api` version** (KRA-44):

- JSON-RPC only; v1.0 method names plus four 0.3 names. ✅ compatible.
- `SubscribeToTask` and push-notification methods return `-32601`. → outbound falls back to polling `GetTask`; no `SubscribeToTask` on this peer.
- SSE emits **0.3 object shapes** (`final` flag, no `statusUpdate`/`artifactUpdate` wrappers) per their TCK notes. → **risk**: our v1.0 client may reject the stream. Mitigation: connection test performs a real `SendStreamingMessage` probe; if the stream shape is invalid, mark connection `streaming: false` and use `SendMessage` + polling. Decision in D-09 whether a narrow shape-normaliser is acceptable.
- Errors carry no `ErrorInfo`; timestamps `+00:00`; `A2A-Version` ignored. Tolerated on the client side (lenient parsing of remote responses, strict on our server).
- `historyLength` ≤ 10; `historyScope` default = whole context. We send `historyLength: 0`.
- `FilePart` supported both directions (`langgraph-api ≥ 0.13`).

## Conformance

- Server: [a2a-tck](https://github.com/a2aproject/a2a-tck) mandatory suite in CI against a local gateway with a stubbed core; [a2a-inspector](https://github.com/a2aproject/a2a-inspector) for manual checks.
- Client: contract tests against `@a2a-js/sdk` sample servers and a recorded LangSmith fixture.
